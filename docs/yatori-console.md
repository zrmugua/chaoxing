# yatori-go-console 本机运行

适用于 0.7.3。App 管理账号学习清单、原版 Console 的配置、进程和输出，学习从原版主程序启动。

## 执行链路

1. 网页进入账号详情，加载课程列表、已保存的选课清单、进度和日志。
2. 开始或应用选课变更后，Worker 为该账号保存课程名称与规则快照，等待旧进程回收。
3. 生成原版 `config.yaml`；用 `includeCourses` 限定此次选中的完整课程名称。
4. 从 Android 安装目录启动 `libyatori_console.so`，原版 `main()` 负责执行。
5. 捕获 stdout / stderr，绑定任务和账号；原始程序退出后记录退出状态。

同名课程需要同时选择，因为原版按名称匹配。各账号具有独立工作目录和单实例锁缓存。系统并发数控制同时启动的账号进程数，视频多课程和多任务点并发交给 Console。

## 配置

`videoModel`、`cxNode`、`cxChapterTestSw`、`cxWorkSw`、`cxExamSw`、`shuffleSw`、`autoExam`、`examAutoSubmit` 与课程范围按原版字段写入。音频、文档、阅读、外链的处理跟随 Console 流程。原版 `videoModel=0` 也会影响其文档和外链分支。

AI 支持原版 Chat Completions 兼容接口及秘塔接口。题库使用 `apiQueSetting.url`。邮件使用原版 SMTP 配置，并在原版流程到达通知时发送。账号代理以 `ip.txt` 接入原版 HTTP 代理池。

`examAutoSubmit=0` 保存，`1` 自动交卷；`2` 对章测检查空题，对课程作业和考试仍自动交卷。界面按该版本的真实行为提示。

## 查询与状态

查询桥接与章节响应解析器作为额外 Go 文件编入同一可执行程序。设置 `YATORI_BRIDGE_MODE` 后进入课程、章节或作业/考试查询入口，调用原版登录和 Core 函数，把结果写入私有 JSON 文件；日志保持标准输出。桥接提供无账号 `selftest`，用于验证 Android 原生程序、ONNX 初始化，以及三份共享模型的实际解析。

运行中修改课程并保存后，后台使用最新清单重启原版程序。暂停和停止会结束当前进程，继续时重新启动；暂停时修改清单仍保持暂停，停止后保留清单。服务重启后正在学习的账号暂停，等待用户继续。退出码 0 记录「执行结束」，其实际结果查看原始日志。

账号详情通过「同步课程列表」读取账号课程，每门课程通过自己的「刷新进度」查询章节，显示完成比例、更新时间及查询状态。运行中同步会临时结束学习进程，串行查询完成后按最新账号状态恢复。当前课程依据原版课程活动日志展示；运行清单记录本次进程配置的全部课程。

章节进度响应中的 `msg`、状态字段和章节编号分别解析；支持数值计数与字符串计数。响应拒绝、计数无效或缺少请求章节时，保留已有平台进度并返回原因。平台提示经过管理服务脱敏后显示在课程行和原始日志中。

每次查询都会创建独立登录会话，并按原版 Console 的顺序先读取课程列表，初始化账号编号。章节和作业/考试查询按课程编号与班级编号匹配当前课程，使用本次返回的课程参数。课程失效或初始化失败时终止查询并保留已有进度；编号缺失、格式异常与设备整数范围限制分别提示。
